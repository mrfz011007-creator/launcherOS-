# V3.2 Integration Audit

## Baseline

This branch consolidates the chained V3.2 control-plane work before integration into `main`.

## Audited invariants

- Task Contract remains authoritative over GitHub Issue trigger text.
- RUN_ID is execution-time generated.
- Runner scope is independently verified.
- Budget exhaustion is terminal for the current run.
- Git checkpoint must match remote.
- Technical verification does not imply product acceptance.
- `VERIFIED` is not `DONE`.
- `VERIFIED → DONE` requires an explicit Project Owner acceptance signal.
- Human acceptance resolves the latest verified execution for the task rather than relying on an absent RUN_ID field in the original issue body.
- No Android, Gradle, release-signing, credential, or product-scope changes are introduced by the control-plane work.

## Current integration state

The control-plane remains separate from the Android product implementation. The next environment-level validation requires a live Codespace smoke test.

## Human gate

No PR in this chain is considered merged or accepted merely because it is technically mergeable. Project Owner approval is required for integration into `main`.
